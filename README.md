## How I work

- Start with the user journey, then design the smallest reliable system behind it.
- Treat loading, error, empty, and permission states as part of the feature — not polish added later.
- Prefer clear boundaries over clever abstractions.
- Measure before optimizing, and document the trade-offs.
- Use demos, tests, and reproducible setup to turn claims into evidence.

## Currently

- Open to frontend and full-stack opportunities.
- Exploring the boundary between product engineering, real-time systems, and low-level rendering.
- Turning project notes into clear architecture and decision records so the work is easy to review.
